# AURA codebase audit — 24–25 October 2026

The audit started from commit `507d81a`, with a clean working tree. The aim was to
remove duplicated logic and fix inconsistencies while keeping every feature working
as before. The changes are small and reversible, and nothing was redesigned. No
dependencies were added and no stored data was changed.

## 1. Summary

**Before:** the codebase was in good shape. It has 715 automated tests (unit, API and
headless-browser) and all of them passed. No linter or type checker is installed, and
none was added. The audit found:

- no data-integrity problems;
- one real reliability bug: after a reboot, the calendar could stay stale for 30 minutes;
- a handful of places where the same rule was written twice and had started to drift
  apart (the network-protection tile vs. its status capsule; time formatting in the
  assistant and Settings);
- unused imports.

**After:**
- Each of those rules now has a single implementation.
- The calendar recovers within 2 minutes of the network coming up.
- Seven regression test cases were added.

## 3. Duplicates found

| Area | Finding | Decision |
|---|---|---|
| UI | The Pi-hole tile and its status capsule each decided "alert / ok" with their own copy of the rules (the capsule ignored `blocking_ok`) | **Merged** into `protectionSummary()` |
| UI | On the Overview tab, each status capsule repeats a tile that is also visible (weather, tips, groceries, ad blocking) | **Left as designed.** The capsules come from the Apple Home-style spec and summarise tiles that are hidden in room tabs. See §8. |
| UI | The weather detail showed sunrise and sunset twice (the "Right now" cards and the Sun card, which also has daylight), and "Feels like" twice (under the big temperature and as a card) | **Removed the repeats.** The "Right now" sunrise/sunset cards appear only when the Sun card can't show them (no Sun & Moon data); "Feels like" stays under the temperature. The clock detail keeps its own sunrise/sunset (a different view). |
| Code | IPv4/IPv6 address parsing written twice in `security.py` | **Merged** (`_ip`) |
| Code | "Add to the shopping list unless the name is already open" written in both `main.py` and `nutrition.PlanGroceries.apply` | **Merged** into `PlanGroceries.add_missing`, which now runs under the same lock as the automatic batches |
| Code | Background-task start-up block repeated 4× in `main.py` | **Merged** (`spawn`) |
| Code | `/api/weather` and `/api/calendar` repeated what the assistant's `current_weather()` and `agenda_for()` already did | **Reused** those helpers |
| Code | Temperature formatting in `assistant.py` and `recommendations.py` | Left: spoken answers say "°F" on purpose and tiles show "°", so they aren't true duplicates |
| Code | `el()` and `api()` helpers copied in four front-end files | Left for now: the copies differ (event handlers, timeouts, error text). Merging needs a shared script on three pages. See §9. |
| Code | `_hhmm` / `_days` validators in `config.py` and `settings_store.py` | Left: they validate different inputs (the `.env` format vs. the Settings JSON) and give different messages |
| Config | Traffic colours hard-coded with the same values as `--ok`, `--accent` and `--danger` | **Replaced** with the tokens (pixel-identical). "Heavy" stays `#ff9f5a`, because `--tone-orange` is slightly different. |
| Data | Polling plus SSE for the same data | Intentional: SSE is primary, polling is the fallback. No duplicate subscriptions or listeners were found. |
| Docs | `HANDOVER.md` said the router hands out the Pi for DNS (it was reverted on 23 Oct), listed real-voice testing as not done, and gave a ~6 min test time | **Corrected** |

## 4. Changes made

| File | Change | Why |
|---|---|---|
| `app/agenda.py` | Unreachable feeds are retried after 2 min; bad content waits the normal 30 min | After the 14:59 boot on 24 Oct, the log shows the calendar unreachable and not retried until 15:29 |
| `app/main.py` | `spawn()` helper; weather and calendar endpoints reuse the shared helpers; the meal note publishes a `meals` event; the add path uses `add_missing` | duplication; the meal note now shows on other screens like ticks do |

| `static/js/app.js` | `protectionSummary()`, a shared `clockTime()`, re-sync of meals, commute and calendar after an SSE reconnect | consistency; screens no longer miss updates made during a network blip |
| `static/js/assistant.js` | Conversation times use the home time zone and the 12/24-hour setting | they used the device's own clock |

| tests | 7 new regression test cases (calendar retry, meal note event, shared add path, assistant clock, weather detail without repeats ×2 sizes, sunrise fallback) | cover the changes |

## 6. Test results

- Baseline (`507d81a`, before any change): 715 passed, 0 failed (≈14 min including headless browser).
- After all changes: **722 passed, 0 failed, 0 skipped** (715 + 7 new test cases).
- Live checks after deploying (`aura` and `aura-voice` restarted):
  - `/api/weather`, `/api/calendar`, `/api/meals/day`, `/api/system/dns-filter` and `/api/assistant` all returned 200.
  - All 3 calendar feeds were OK and the voice worker plus wake word were active.
  - The dashboard showed no console errors and no horizontal scroll at 1920×1080 or 1280×720.
- No lint or type checks were run: no such tools are installed.

## 7. Performance (measured on the Pi, 24 Oct 23:46)

- `aura` (dashboard server): 81 MB RSS, about 1% CPU.
- `aura-voice`: 1.1 GB RSS (speech models in memory), about 5% CPU averaged over 7.5 h,
  from the always-on wake word. Expected for local speech; turning the wake word off in
  Settings brings it close to idle.
- Memory: 8 GB, about 5 GB available. Disk: 34% used. Logs rotate at 1 MB × 3 (2.6 MB total).
- Dashboard polling: commute, protection and system every 60 s; weather and meals every
  few minutes; groceries only when SSE is down. Nothing excessive was found, so no
  performance changes were made.

## 8. Outstanding issues (left alone on purpose)

1. **Router DNS reverted to `192.168.1.1`** (23 Oct, 02:14), so ad blocking isn't
   network-wide. This is a router change, so it's left to the household (deferred earlier).
2. **Status capsules repeat visible tiles on the Overview tab.** Hiding a capsule while
   its tile is on screen would remove the repetition, but it changes the agreed design.
   It needs the household's decision.
3. If the shopping list fills up (500 items) partway through a multi-item **Add**, the
   items added before the limit are kept, but other screens only see them at their next
   refresh. This was already the case before the audit; the limit is unlikely to be reached.
